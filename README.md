# DevLens 0.1.1 — Android engineering console

Первая устанавливаемая beta: нативное Android-приложение с локальным интерфейсом HTML/CSS/JS. Минимум Android 8 (API 26), актуальный Android System WebView. APK не зависит от внешнего веб-сайта. Это development-сборка для установки через ADB, не публикация в Google Play.

## Что реализовано

- **CSS-пульт:** карточки RAM, батареи, SSH, AI, музыки, напоминаний. Скрытие, восстановление, изменение порядка, пять акцентных цветов, редактор пользовательского CSS. `data-widget` позволяет стилизовать конкретную карточку.
- **Linux Control:** несколько профилей серверов, пароль / приватный SSH-ключ с passphrase, подтверждение ключа сервера при первом соединении, сохранение known_hosts. Запуск команд с явным подтверждением, вывод stdout/stderr, exit code, пресеты Docker, systemd, journalctl, память, диски. Проверка SSH-входа без запуска команды, сообщения об ошибках подключения и живой вывод. Чтение метрик по запросу. Современные ключи поддерживаются JSch и Bouncy Castle.
- **Network Lens:** DNS, TCP-проверка до 32 выбранных портов, время соединения, проверка цепочки и имени TLS-сертификата на 443.
- **API Lab:** HTTP-метод, URL, JSON-заголовки, тело, статус, длительность, заголовки ответа, сохранённые запросы. Ответ ограничен 2 МБ; перенаправления не выполняются автоматически.
- **Realtime Lab:** WebSocket и MQTT 3.1.1 over WebSocket: подключение, username/password, публикация QoS 0, подписка QoS 0, keepalive. Требуется WebSocket endpoint брокера, обычный MQTT TCP :1883 не поддерживается.
- **AI Hub:** OpenAI-compatible Chat Completions API; Base URL, API key, model, дополнительные заголовки, temperature, max_tokens, timeout, загрузка /models. Чат и явное добавление контекста SSH/HTTP/диагностики. API-ключ не нужен для остальных модулей. Команды AI автоматически не исполняются.
- **Sensor Lab:** акселерометр, гироскоп, магнитометр, график, CSV через Android file picker; микрофонный спектр 80 Гц–7.2 кГц и dBFS. При уходе в фон запись прекращается.
- **QR Console:** камера сканирует QR, генерация меток для серверов и оборудования, заметки и связь с сервером. Произвольный QR показывается как текст и не исполняется.
- **Music:** системный выбор нескольких локальных аудиофайлов с автоматическими названиями и сохранённым доступом, HTTP(S) аудиопотоки/радио, поиск и случайные треки Subsonic/Navidrome. Android foreground service, очередь в сервисе, media session, пауза и остановка в уведомлении, управление с экрана блокировки, реакция на потерю audio focus/отключение наушников.
- **Напоминания:** системные уведомления, разовое или повтор через 24 часа / 7 дней, отмена, восстановление после перезагрузки.
- **Сценарии:** редактируемые JSON-цепочки HTTP, SSH, delay, reminder с последовательным выполнением, журналом и остановкой при ошибке. Запуск вручную.
- **Mock Server:** JSON endpoint на телефоне, порт, HTTP status и задержка до 5 секунд, журнал запросов. Работает пока жив процесс приложения.
- **Утилиты:** JSON format, JWT decode, Unicode Base64, URL encoding, SHA-256; командная палитра; журнал действий.

## Границы этой beta

Это не вся большая концепция из обсуждения. Ещё не реализованы: пространственный AR; непрерывный Linux-агент с метриками, логами и фоновыми событиями; захват запросов сайтов на компьютере; интерактивный SSH TTY; обнаружение всех устройств и карта сети; визуальный редактор сценариев и автоматические триггеры; расширения; проверка восстановления бэкапов; режим презентации; NFC-сценарии; потоковые ответы и tool calling AI. Текущие экраны работают с перечисленными выше функциями, а не изображают эти отсутствующие возможности.

SSH-команда ограничена 60 секундами и 512 КБ вывода. Разрыв SSH не гарантирует остановку процесса на сервере. Для `sudo` используйте заранее настроенные разрешённые команды: интерактивный ввод пароля не поддержан.

Android может задерживать неточные уведомления в Doze. Force stop запрещает фоновое выполнение до следующего запуска. Повторы задаются интервалом, не календарным локальным временем. WebSocket/MQTT не предназначены для надёжного фонового мониторинга. Музыкальные потоки должны быть прямыми URL, не страницами YouTube/Spotify; DRM не поддерживается. Для Subsonic используется salt/token авторизация.

## Подключение

1. Откройте «Объекты → Сервер», введите IP/домен, порт, пользователя и пароль либо приватный ключ. При первом SSH сверяйте fingerprint.
2. Для AI: «AI Hub → Провайдер». Base URL заканчивается на `/v1`, если это требует провайдер; приложение добавляет `/chat/completions` или `/models`. Различные проприетарные API требуют адаптера и не считаются автоматически совместимыми.
3. В Music добавьте локальный файл, прямой URL потока или Subsonic-сервер.
4. Разрешения камеры, микрофона и уведомлений запрашиваются при первом использовании соответствующей функции. После выдачи разрешения повторите действие.
5. Для CSS: «Настройки → CSS-виджеты», например:

```css
.card { border-radius: 16px; }
[data-widget="music"] { border-color: #8bb7ff; }
```

Данные приложения (включая пароли и API keys) шифруются AES-GCM с ключом Android Keystore. Резервное копирование ОС отключено. Чужие страницы не загружаются в WebView с нативным мостом. HTTP разрешён для локальных инструментов; для внешних секретов используйте HTTPS. Из чата в AI отправляются сообщения и явно добавленный пользователем контекст.

## Сборка

```bash
ANDROID_SDK_ROOT=/path/to/android-sdk DEVLENS_JDK=/path/to/jdk17 ./build.sh
```

Нужны Android platform 34, build-tools 34.0.0, JDK 17. R8 8.5.35 и зависимости включены в проект. По умолчанию скрипт использует уже найденный SDK на этой машине. Результат: `../DevLens.apk`.

Подпись — development key в `signing/devlens-debug.jks`, alias `devlens`, пароль `android`. Сохраняйте этот ключ для обновления установленной beta без удаления её данных. Не используйте его для публичного release.

Установка, когда подключён нужный телефон и подтверждена USB-отладка:

```bash
adb devices -l
adb -s DEVICE_SERIAL install -r ../DevLens.apk
adb -s DEVICE_SERIAL shell am start -n app.devlens/.MainActivity
```

Всегда выбирайте serial телефона явно, особенно если ADB также видит телевизор или другие устройства.

## Проверки

- Java компиляция + D8, упаковка APK, проверка подписей APK v2/v3.
- Browser UI: 16 экранов, mobile layout, сохранение и экранирование данных, Base64/SHA-256, виджеты.
- Интеграция интерфейса с **тестовым** Android-мостом: HTTP, SSH, AI, напоминания, сенсоры, mock server. Это не заменяет запуск на реальном Android.
- Физический телефон ещё не подключался: камера, датчики, разрешения, media session, SSH и уведомления требуют проверки на нём. Реальный API key или реальные серверные реквизиты не использовались.

Документация платформы: [WebView](https://developer.android.com/develop/ui/views/layout/webapps/webview), [AlarmManager](https://developer.android.com/reference/android/app/AlarmManager).
